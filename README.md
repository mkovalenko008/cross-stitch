# Схема для вышивки крестом из картинки

Статический сайт: загружаете картинку, получаете схему для вышивки крестом
шириной **от 20 до 1000 крестиков** (высота — по пропорциям картинки).
Всё считается в браузере. Бэкенда нет, картинка никуда не отправляется.

Что получается на выходе:

- `<имя>_схема.pdf` — обложка (превью, размер, число цветов, карта страниц) и сама схема
  кусками по 60×80 клеток на лист A4: заливка цветом нитки, символ, сетка с жирными линиями
  через 10 клеток, нумерация по краям, стрелки центра;
- `<имя>_цвета.pdf` — ключ: символ, образец, номер нитки, название, число крестиков и пасм;
- `<имя>.oxs` — файл Open Cross Stitch для Cross Stitch Saga и других программ
  (формат `.saga` закрытый, но Saga импортирует OXS);
- «Скачать всё» — те же три файла в zip.

Нитки на выбор: **DMC** (489 цветов) или **Гамма** (594 цвета).

Стиль схемы на выбор:

- **Как на фото** (по умолчанию). Оттенки, которых нет среди ниток, собираются из соседних
  крестиков, как точки в живописи. Сайт сам подбирает вариант с наименьшим числом одиночных
  крестиков, при котором **сходство с фото не ниже 85%** (порог меняется в «Дополнительно»).
- **Ровные пятна.** Каждая клетка — ближайшая нитка, без дизеринга. Проще вышивать,
  но плавные переходы превращаются в ступеньки, а оттенки между нитками теряются.

Пример на картинке 957×1280, 400 крестиков: у «Ровных пятен» сходство с фото — 36%,
у «Как на фото» — 86% (DMC, одиночных крестиков 8%) и 85% (Гамма, одиночных 1%).

## Как запустить у себя

Нужен [Node.js](https://nodejs.org/) версии 20 или новее.

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает команда, обычно http://localhost:5173/cross-stitch/.

Другие команды:

| Команда | Что делает |
|---|---|
| `npm test` | юнит-тесты (Vitest) |
| `npm run build` | сборка сайта в папку `dist/` |
| `npm run preview` | посмотреть собранный сайт локально |
| `npm run palettes` | заново скачать и собрать палитры (нужен интернет) |
| `npm run check-samples -- картинка.png 100 300` | собрать схемы на 100 и 300 крестиков из PNG и сложить PDF и OXS в `samples-out/` |
| `npx vite-node scripts/symbol-sheet.ts` | тестовая схема, где встречаются все 618 символов |
| `npx vite-node scripts/build-symbol-metrics.ts` | пересчитать габариты символов после правки их списка |

## Как выложить на GitHub Pages

Сайт публикуется автоматически при каждом push в ветку `main`.
Workflow лежит в `.github/workflows/deploy.yml`: он ставит зависимости, прогоняет тесты,
собирает сайт и выкладывает его.

Первый раз:

1. На github.com нажмите **+** → **New repository**. Имя, например, `cross-stitch`.
   Репозиторий публичный, README не добавляйте. Нажмите **Create repository**.
2. Отправьте туда код (в папке проекта):
   ```bash
   git remote add origin https://github.com/<ваш-логин>/cross-stitch.git
   git push -u origin main
   ```
3. В репозитории откройте **Settings** → **Pages**. В **Build and deployment** → **Source**
   выберите **GitHub Actions**.
4. Во вкладке **Actions** дождитесь зелёной галочки у «Деплой на GitHub Pages»
   (1–2 минуты). Если первый запуск упал до шага 3, нажмите **Re-run all jobs**.
5. Сайт появится по адресу `https://<ваш-логин>.github.io/cross-stitch/`.

Путь сайта (`base` в `vite.config.ts`) workflow подставляет сам по имени репозитория,
поэтому репозиторий можно назвать как угодно. Локально по умолчанию используется `/cross-stitch/`.

## Откуда палитры

Файлы `src/palettes/dmc.json` и `src/palettes/gamma.json`: массив `{ code, name, rgb: [r, g, b] }`.
Собираются скриптом `scripts/build-palettes.mjs`. Цвета не выдумывались: номер без данных
в палитру не попадает.

**DMC — 489 цветов** (мулине Mouliné Spécial, арт. 117), включая Blanc, Ecru, B5200 и
цвета 01–35, добавленные в 2017 году. Источник:
[makebead/craft-color-codes](https://github.com/makebead/craft-color-codes), файл `data/json/dmc-floss.json`
(коммит `84dbdc2`, лицензия данных CC BY 4.0, «Color data: craft-color-codes by
[MakeBead](https://makebead.com/)»). Авторы сверили три независимых источника
(floss.maxxmint.com, набор adrianj/CrossStitchCreator, xstitchify.com) и исправили известные
ошибки старых таблиц: DMC 309, испорченные Excel HEX-коды. Список из 489 номеров мы
дополнительно сверили с floss.maxxmint.com: номера совпадают. В названиях поправлены только
опечатки: «Vy» → «Very», «Darkv» → «Dark», двойные пробелы. Сами цвета не менялись.

**Гамма — 594 цвета.** Источник — официальная
[карта цветов мулине Gamma](https://firma-gamma.ru/articles/colormap-muline/gamma/) на сайте
фирмы «Гамма». В таблице у каждого номера есть образец цвета, опубликованный производителем.
Разные номера Гаммы под одним и тем же DMC имеют разные образцы: значит, это цвет самой
нитки Гаммы, а не подставленный цвет DMC.

- у всех 594 цветов RGB взят из официальных образцов, поле `"rgbSource": "gamma-official"`;
- цветов с приблизительным RGB по аналогу DMC (`"rgbSource": "dmc-equivalent"`) — **0**:
  такой подстановки не понадобилось;
- в поле `dmc` лежат аналоги DMC по официальной таблице: они есть у 514 цветов, у 52 из них
  аналог помечен производителем как «наиболее похожий цвет» (в данных со звёздочкой, `"564*"`);
- 80 цветов аналога DMC не имеют;
- официальных названий у ниток Гаммы нет, поэтому в `name` записан аналог DMC,
  например `DMC 3713 Salmon Very Light` или `≈ DMC 445 Lemon Light`. Если аналога нет,
  название пустое, а в PDF стоит «—».

Цвета на экране и в PDF приблизительные (монитор, принтер, освещение). Покупайте нитки по номеру.

## Как считается схема

1. **Ресайз усреднением по площади.** Каждая клетка — среднее всех пикселей исходника,
   попавших в неё; пиксели на границе клеток учитываются долями. Усреднение идёт в линейном RGB,
   а не в sRGB, и с учётом прозрачности. Очень большие фото (больше 16 Мп) сначала уменьшаются
   до 16 Мп: иначе Safari на iPhone не даёт их прочитать. Для схемы до 1000 крестиков это без потерь.
   Если крестиков больше, чем пикселей в картинке, сайт предупреждает: новых деталей не появится.
2. **CIELAB (D65).** Цвета клеток и ниток переводятся в Lab.
3. **Эталон.**
   - «Ровные пятна»: каждой клетке — ближайшая нитка палитры по CIEDE2000. Поиск точный: палитра
     отсортирована по L*, и перебор отсекается по нижней границе ΔE00 ≥ |ΔL|/S_L. Тест проверяет,
     что результат совпадает с полным перебором.
   - «Как на фото»: рассеивание ошибки Флойда–Стейнберга в линейном RGB (змейкой), ближайшая
     нитка — по CIEDE2000. Найденные нитки запоминаются для оттенков с шагом 2/255, чтобы
     1000 крестиков считались за секунды; ошибка всё равно считается от настоящего цвета клетки.
4. **Меньше одиночных крестиков** (только «Как на фото»). Обычный дизеринг даёт около половины
   одиночных крестиков. Два приёма:
   - *отрезки от двух крестиков* прямо при дизеринге: если в строке начался новый цвет, следующая
     клетка берёт тот же, когда он не сильно хуже лучшей нитки (допуск в ΔE2000); ошибка
     переносится дальше, поэтому средний цвет не теряется;
   - *уборка*: клетка без соседа своего цвета перекрашивается в цвет соседа, если средний цвет
     окрестности 3×3 (то, что видно издалека) от этого почти не меняется.
   Сочетания допуска и силы уборки выстроены в лестницу `SMOOTH_LEVELS` (`src/core/pattern.ts`)
   от самого чистого к самому точному. Двоичным поиском выбирается самый чистый уровень, у которого
   сходство с фото не ниже заданного (по умолчанию 85%). Для сеток больше 160 000 клеток поиск идёт
   на уменьшенной копии, а итог проверяется на полной сетке. Если не дотягивает даже самый точный
   уровень, берётся он, и сайт пишет, что в палитре не хватает оттенков.
5. **Чистка редких цветов.** Пока есть цвет, у которого крестиков меньше минимума
   (по умолчанию 10), самый редкий убирается. Каждая его клетка получает ближайший по CIEDE2000
   цвет из оставшихся в схеме. Расстояние считается от усреднённого цвета самой клетки.
6. **Точность передачи цвета** — доля клеток, у которых итоговая нитка совпадает с эталонной
   или отличается от неё на ΔE2000 ≤ 2. Цель — не меньше **99,9%**. Если после чистки точность ниже,
   минимум автоматически уменьшается: заданный → 10 → 7 → 5 → 3 → 2. Ниже 2 он не опускается,
   поэтому цветов с одним крестиком в схеме не бывает. Если даже при 2 точность меньше 99,9%,
   результат всё равно выдаётся, а сайт честно показывает цифру.
   Эта метрика показывает, сколько потеряно при удалении редких цветов, а не насколько схема
   похожа на фото. Для этого есть отдельный показатель — сходство.
7. **Сходство с фото** — насколько схема издалека похожа на исходник. Картинка и схема слегка
   размываются (гаусс 3×3 — так вышивку видит глаз с обычного расстояния), и считается доля
   клеток, где разница ΔE2000 ≤ 3. Цель для «Как на фото» — не меньше 85%. Ограничение —
   сама палитра ниток: в каких-то тонах (например, тёмных сизо-лиловых у DMC) ниток мало, и чтобы
   собрать нужный оттенок, приходится оставлять больше одиночных крестиков.
8. **Символы.** Самым частым цветам достаются самые простые символы: контурные фигуры, цифры,
   латиница. Всего 618 уникальных глифов — больше, чем цветов в любой палитре, поэтому цвета
   никогда не урезаются из-за нехватки символов. Первые 348 подобраны без визуальных двойников:
   нет O рядом с 0, кириллицы, похожей на латиницу, и т. п.; остальные — резерв для схем
   с очень большим числом цветов. Тест проверяет, что каждый символ есть во встроенном шрифте
   DejaVu Sans. В PDF символ центрируется в клетке по реальным габаритам глифа. Цвет символа,
   чёрный или белый, выбирается по контрасту с заливкой. Клетки на страницах схемы пишутся
   прямо командами PDF, поэтому схема на 1000 крестиков собирается за несколько секунд.

Пасмы: 1 пасма (8 м, 6 сложений) ≈ 1800 полных крестиков на Aida 14 в 2 сложения.
Округление вверх, минимум 1. Константа `STITCHES_PER_SKEIN` — в `src/core/constants.ts`.

## Формат OXS

Open Cross Stitch 1.0. Структура сверена с
[описанием формата от Ursa Software](https://www.ursasoftware.com/OXSFormat/) (авторы
формата, MacStitch и WinStitch) и с файлом, который записала их программа
(`Piggies.oxs` из открытого проекта [Embroiderly](https://github.com/embroidery-space/embroiderly)):

- `format` — стандартный блок комментариев;
- `properties` — размер (`chartwidth`, `chartheight`), `charttitle`, `stitchesperinch="14"`, `palettecount`;
- `palette`: элемент 0 — ткань (`number="cloth"`), дальше нитки. Номер записан как у Ursa —
  `number="DMC    310"` или `number="Gamma   0001"`, плюс название, `color` в HEX и `strands="2"`;
- `symbol`: у Ursa это номер глифа в их собственном шрифте, другие программы указывают код символа
  и шрифт. Здесь записан код Unicode символа из PDF и `fontname="DejaVu Sans"`. Программа,
  которая этот шрифт не знает, может показать свои символы, но цвета и номера ниток сохранятся;
- `fullstitches` — по элементу на каждую непустую клетку, координаты `x`, `y` с нуля;
  пустые клетки не записываются;
- пустые `partstitches`, `backstitches`, `ornaments_inc_knots_and_beads`, `commentboxes`.

## Устройство проекта

```
src/
  core/        алгоритм: цвет и CIEDE2000, ресайз, подбор, дизеринг, чистка, символы, константы
  palettes/    dmc.json, gamma.json
  pdf/         схема и ключ цветов (jsPDF), PNG-превью для обложки
  export/      OXS
  workers/     фоновый поток: расчёт схемы и сборка файлов, чтобы интерфейс не зависал
  main.ts      интерфейс
tests/         юнит-тесты
scripts/       сборка палитр, метрики символов, прогон на тестовых картинках
public/fonts/  DejaVu Sans (обычный и жирный) для PDF
```

Стек: Vite + TypeScript без фреймворка, jsPDF, JSZip, fflate. Тесты — Vitest.
Шрифт — [DejaVu Sans](https://dejavu-fonts.github.io/) 2.37, свободная лицензия
(`public/fonts/DejaVu-LICENSE.txt`).
